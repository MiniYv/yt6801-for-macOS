## 一、这东西到底是什么

一句话：**一个跑在用户态的 DriverKit 驱动（dext），把 macOS 原本完全不认识的 YT6801 网卡，接管成一个正常的 `en4` 以太网接口。**

- 不是 kext。内核里一个字节的驱动代码都没有，驱动跑在独立进程里。
- 它通过 `IOUserNetworkEthernet` 家族把自己注册给 macOS 网络栈（Skywalk），
  于是 `ifconfig` 能看见它、`configd` 能给它配 IP、路由表能加条目。
- 硬件侧：mmap 到 PCIe BAR，操作 YT6801 的 MAC 寄存器（DWC 兼容）、
  MDIO 总线、PHY、以及 TX/RX 两个 DMA 描述符环。

**为什么必须 DEXT**：kext 会直接把内核 panic，且新系统的内核扩展加载策略对无签名 kext 等于关门。
DEXT 崩了只是进程重启，内核不受影响。

## 二、架构

```
┌──────────────────────────────────────────────────────┐
│  macOS 网络栈 · Skywalk / IOUserNetworkEthernet       │
└───────────────────────┬──────────────────────────────┘
                        │ 四队列（TX/RX 提交 + 完成）+ 包池
┌───────────────────────▼──────────────────────────────┐
│  dext 进程（用户态，非内核）                            │
│  ┌────────────────────────────────────────────────┐  │
│  │ Start/Stop · 注册接口 · 上报链路                  │  │
│  ├────────────────────────────────────────────────┤  │
│  │ hardwareInit · BAR0+0x2000 · MDIO/PHY · DMA 复位 │  │
│  ├────────────────────────────────────────────────┤  │
│  │ 数据面 · 门铃驱动（MSI-X 不送达）                 │  │
│  │   TX serviceTx → 自建缓冲 → TDES0..3             │  │
│  │   RX serviceRx ← 自建缓冲 ← RDES0..3             │  │
│  └────────────────────────────────────────────────┘  │
└───────────────────────┬──────────────────────────────┘
                        │ PCIe
┌───────────────────────▼──────────────────────────────┐
│  YT6801 MAC（DWC 兼容）→ PHY                          │
│  当前：PHY 数字回环常开（无网线自环验证）               │
└──────────────────────────────────────────────────────┘
```

### 关键设计：收发都走自建 DMA 缓冲

```
栈的包（CPU 视图） ──memcpy──► 自建 2 KB 缓冲（DMA 可见） ──描述符──► 硬件
                                                              │
栈的包（CPU 视图） ◄──memcpy── 自建 2 KB 缓冲（DMA 可见） ◄──描述符── 硬件
```

包池的 IOVA 在这颗 MAC 上收发都不可用，表现是"描述符正常、长度正常、内容错"。
每槽 2 KB × 128 槽 × 2 方向 = 512 KB，代价是一次多余的 memcpy，换来正确性。

### 一帧数据怎么走

**发送**：栈放进 TX 提交队列 → 门铃 `TxDataAvailable` → `serviceTx` 取包
→ memcpy 进 `txSlot[txHead]` → 填 TDES0..3（低/高 32 位地址、长度、FD/LD/FL、OWN）
→ 写 TDTR → 硬件 DMA 读 → MAC 加前导码/FCS → PHY 发出。

**接收**：`refillRx` 预挂 128 个描述符 → 硬件写进 `rxSlot[i]`、回写 RDES3（PL、OWN 清零）
→ `serviceRx` 扫环、校验帧长和 EtherType → memcpy 进包池的包
→ 交回 RX 完成队列 → 栈收到。

## 六、接了网线之后是什么效果

### 6.1 现在直接插上——不会有变化

dext 已在 `selfLoopMode`，`pollLinkStatus` 在回环期间永远不读真实链路。
插上后接口仍 `UP`，还是自己发自己收。**必须先重载 dext**（本轮按要求保留了自环）。

### 6.2 重载之后（预期）

PHY 拿到 link → 退出回环（BMCR 回 `0x1140`）→ 不打 `MAC_CR.LM`、不开 `PFR.PR|RA`
→ 上报 1000M 全双工 → DHCP 走通拿 IP → 有默认路由能上网 → 拔插由 PHY 中断驱动。

### 6.3 剩余风险

1. **吞吐上不去**：无中断、单队列、单段、每帧两次 memcpy。千兆实际估计 200~500 Mbps。
2. **MAC 地址随机**：开了 MAC 绑定的路由器可能不给 IP。
3. **MTU 1500 可用**：1514 + VLAN 4 = 1518 < 2048，常规场景没问题。

## 八、你自己怎么验证

```bash
# 接口与计数
ifconfig en4
netstat -I en4 -b

# 扩展是否在跑
systemextensionsctl list | grep yt6801

# 驱动日志
/usr/bin/log show --last 5m --predicate 'eventMessage CONTAINS "yt6801"' | tail -30

# 自环收发（计数应同步增长、Ierrs/Oerrs 保持 0）
ping -c 100 -i 0.01 10.99.99.255
netstat -I en4 -b
```

判断标准：
- `Ipkts` / `Opkts` 同步增长、`Ierrs`/`Oerrs` 为 0 → 通路正常
- 日志出现 `丢弃幽灵帧` / `rxGhost` 增长 → 长度校验在拦东西
- `txLong` 增长 → 栈在发超 MTU 的聚合包（说明 TSO 标志仍被误用）
