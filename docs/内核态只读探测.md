# 内核态只读探测（不重启路径）

## 为什么有这条路

DEXT 的加载受 boot-arg `dk=0x8001` 控制，而这个开关**只在启动时读一次**，
没有任何用户态手段能在运行时更改。所以只要不重启，DEXT 在本会话内就加载不了。

传统 kext 走的是完全不同的策略链——SIP 的 `Kext Signing`。
本机状态：

```
System Integrity Protection status: unknown (Custom Configuration)
    Kext Signing: disabled          ← 关键
```

而且这台机器本来就跑着一排第三方 kext（Lilu、VirtualSMC、AMFIPass、NVMeFix…），
说明这条路是活的。kext 不需要重启、不需要开发者账号、不需要 `dk=0x8001`。

## 前提（已逐项验证）

| 项 | 状态 |
|---|---|
| Kext Signing | disabled ✅ |
| `/sbin/kextload` | 存在 ✅ |
| 第三方 kext 在跑 | 是，10+ 个 ✅ |
| YT6801 设备在位 | `pci1f0a,6801`，BAR0 16 KB ✅ |
| 编译工具链 | CLT clang + MacOSX26.2.sdk ✅ |
| kext 产物 | 31 KB，Mach-O kext bundle x86_64，adhoc 签名 ✅ |

## 怎么跑

```bash
bash scripts/build_kprobe.sh      # 构建（不需要 root）
sudo bash scripts/load_kprobe.sh  # 加载 → 探测 → 打印 → 卸载（约 3 秒）
```

`load_kprobe.sh` 会自己完成加载、抓日志、卸载三件事，不需要你记第二条命令。

## 这个模块做什么

绑定 YT6801，映射 BAR0，**只读**以下寄存器，打到内核日志后立刻放弃设备：

| 偏移 | 寄存器 | 期望 |
|---|---|---|
| 0x0000 | MAC_CR | 上电默认值 |
| 0x0008 | MAC_PFR | 包过滤默认值 |
| 0x00B0 | MAC_ISR | 中断状态 |
| 0x0200 | MDIO_ADDR | busy 位应为 0 |
| 0x0204 | MDIO_DATA | — |
| 0x0300 | MACA0HR | MAC 地址高 16 位 |
| 0x0304 | MACA0LR | MAC 地址低 32 位 |
| 0x1000 | DMA_MR | SWR 位应为 0 |
| 0x1008 | DMA_ISR | — |
| 0x1114 | TDLR | 未初始化应为 0 |
| 0x111C | RDLR | 未初始化应为 0 |

这些偏移全部来自 Linux `fuxi-gmac-reg.h`，与 DEXT 版驱动用的是同一份定义。
读出真实值就能验证：**寄存器地图是对的，MAC 地址是真实烧录的**。

## 安全边界（为什么不会把机器搞崩）

1. **全程只读**。代码里没有任何 `Write32`、没有任何配置空间写。
2. **每个偏移读之前校验** `offset + 4 <= 映射长度`，绝不越界。
3. **先校验 vendor/device**，不是 `0x1F0A/0x6801` 就立刻退出，绝不碰陌生设备。
4. **无循环等待、无 DMA、无中断注册、无内存分配**。
5. **`start()` 返回 `false`**：探测完立刻放弃设备。IOKit 认为本驱动不认领它，
   设备不会被占用——DEXT 或任何其他驱动随时可以接手。
6. 脚本加载后**立即 kextunload**，代码不留在内核里。

## 会看到什么

```
YT6801KPROBE: === 开始探测（只读，无写入，无 DMA） ===
YT6801KPROBE: PCI 身份 vendor=0x1f0a device=0x6801 bar0=0xf7c00004
YT6801KPROBE: BAR0 映射成功：虚拟地址非空=true 长度=16384 字节
YT6801KPROBE: MAC_CR   [0x0000] = 0x...
YT6801KPROBE: ...
YT6801KPROBE: MAC 地址 = xx:xx:xx:xx:xx:xx
YT6801KPROBE: 探测完成，释放设备（start 将返回 false，不占用硬件）
YT6801KPROBE: === 探测结束 ===
```

## 如果失败

**加载就被拒**（`kextload` 非零返回）：
- 多半是签名策略。先把 kext 复制到 `/Library/Extensions` 再加载；
- 或者 `sudo systemextensionsctl developer on` 后重试。

**加载成功但日志里没有 `YT6801KPROBE`**：
- `start()` 没被调用，是 `IOPCIMatch` 没匹配上。
- 跑 `ioreg -l -p IODeviceTree | grep -c 'pci1f0a,6801'` 确认设备还在。

**读到 0xFFFFFFFF**：
- 越界保护触发的哨兵值。说明映射长度比预期短，需要重新核对 BAR0 大小。

## 这条路能证明什么、不能证明什么

**能**：寄存器偏移正确、BAR 通路可用、MAC 地址真实存在、PHY 可访问（如果加 MDIO 读）。

**不能**：还不能证明能过包。那需要 DEXT 加载成功、接口 up、ping 通。

但比起纯离线模型验证，这是第一次触达真实硅片。
