# YT6801 黑苹果驱动：构建与加载

> 目标机：RTX 5060 + Ryzen 9 8940HX，macOS 26.7.1 (25G241)，无 Apple 开发者账号

## 一句话结论

**驱动已经能编译成真正的 `.dext`，能签名，能被 DriverKit 加载器识别（`__osclassinfo` 段就位）。**
剩下唯一没做的动作是改 `nvram boot-args` 加 `dk=0x8001` 并重启 —— 这一步会动系统启动参数，交给你决定。

硬件已确认在位：

```
ioreg: "compatible" = <"pci1d05,7011","pci1f0a,6801","pciclass,020000">
       IOName = "ethernet"   pcidebug = "4:0:0"   BAR0 = 16384 字节
       "IOServiceDEXTEntitlements" = (("com.apple.developer.driverkit.transport.pci"))
```

当前 `ethernet@0` 没有任何子驱动，`ifconfig -l` 里也没有对应接口 —— 位置是空的，DEXT 可以占。

## 为什么之前编译不过（根因只有一个）

**sysroot 挂错了。**

| 错误做法 | 后果 |
|---|---|
| `-isysroot MacOSX.sdk -I Kernel.framework/Headers` | `MacTypes.h` 重定义 `UInt64`/`bool`；`libkern/libkern.h` 与 `IOLib.h` 抢 `ffs`；`libkern/copyio.h` 缺 `OS_ALWAYS_INLINE` |
| `-I` 某个 shim 目录 | 带进假的 `DriverKit/` 头，覆盖真头 |

**正确做法**：`-isysroot` 直接指向 `DriverKit.sdk` 本身。它在 `SDKSettings.json` 里写着
`DRIVERKITROOT = /System/DriverKit`，是**自包含**的 —— libc、`os/*`、libc++ 全在自己的
`System/DriverKit/usr/include` 下，**不需要** `MacOSX.sdk`，更**不需要**内核头。

真实 DriverKit SDK 里连 `IOKit/` 目录都不存在，所以 `#include <IOKit/IOLib.h>` 从一开始就是错路径，
正确写法是 `#include <DriverKit/IOLib.h>`。

## iig 的三个必要条件

iig 不是可选工具：`.iig` 就是类声明的唯一来源，它生成 `.h`（类定义 + `_Start_Args` 参数宏 + 元类 +
`__DATA_CONST,__osclassinfo` 注册段）和 `.iig.cpp`（RPC 分发胶水）。

1. **`-D__IIG=1`** —— 不传，`OSObject.iig` 里 `#define KERNEL IIG_KERNEL` 整块被跳过，
   报 `variable has incomplete type 'class KERNEL'`。
2. **`--header` 必须落在 `$GEN/<bundle-id>/<Class>.h`** —— iig 生成的 `.iig.cpp` 里写死了
   `#include <bundle-id/Class.h>`，路径不对就 `file not found`。
3. **不能给 iig 传 `-target`** —— 它自己已经设了，重复传报
   `error: -target is only permitted with an unknown arch`。

## 加载前提（三件，缺一不可）

| 项 | 本机现状 | 说明 |
|---|---|---|
| SIP | Custom，Kext Signing disabled | ✅ 已满足 |
| `amfi_get_out_of_my_way=0x1 amfi=0x80` | ✅ 已在 boot-args | ✅ 已满足 |
| `dk=0x8001` | ❌ **缺** | 关掉 DriverKit entitlement 校验 |

补上（会写 nvram，需重启）：

```bash
sudo nvram boot-args="$(nvram boot-args | sed 's/boot-args[[:space:]]*//') dk=0x8001"
sudo systemextensionsctl developer on
# 重启
sudo ./scripts/install.sh
```

> 有实测记录指出：AMFI 完全禁用会让 DEXT 启动报 `Exec format error` (Code 8)。
> 本机同时设了 `amfi=0x80` 和 `amfi_get_out_of_my_way=0x1`，如果重启后撞上这个，
> 先只留 `amfi=0x80` 试。

## 已实现 / 未实现

**控制通路（全部取自 Linux 1.0.30 真实值）**

- 寄存器地图：MAC `0x0000~0x030C`、DMA `0x1000~0x1088`、通道 `0x1100+0x80*n`、MTL `0x0D00+0x40*n`
- MDIO：`(reg << 16) | 0x8000200D` 读 / `0x80002005` 写，busy 轮询 15 次
- 扩展寄存器窗口：`0x1E` 地址 / `0x1F` 数据
- MAC 地址读取：`MAC_MACA0HR/LR` 位域重排，EFUSE 空白时退本地管理地址
- DMA 软复位：`DMA_MR.SWR` 置位等自清零
- **PHY 内部回环自检**：`BMCR 0x8140` 进 / `0x9140` 出，扩展 `0x3A18`/`0x6812`，`SPEC_STATUS` 链路位

**数据通路（新增）**

| 部件 | 实现 |
|---|---|
| 描述符环 | 128/128 条，16 字节 × 4 word，`IOBufferMemoryDescriptor` + `IODMACommand`，**强制校验单段物理连续** |
| TX | 单缓冲帧：`desc2.B1L` 放长度（**不是 desc3**）、`FD|LD`、`IC`；屏障后置 `OWN`；尾指针写**下一条空描述符的设备地址**到 `TDTR_LO` |
| RX | `OWN|BUF1V|INTE` 挂包；收割时读 `desc3[14:0]` 长度、`ES`(bit15) 判错；坏帧回收缓冲、不发栈 |
| 中断 | `kIOInterruptTypePCIMessaged` + `IOInterruptDispatchSource`，读 `DMA_ISR`/`DMA_CH_SR`/`MAC_ISR` 后写 1 清 |
| 门铃 | 两个提交队列 `CopyDataQueue` → `SetDataAvailableHandler` + `SetEnableWithCompletion` |
| 队列管理 | MTL `TQS/RQS=0x3F`（16 KB）、`RSF` 存储转发、`FEP` 错误帧前向 |
| MAC | `CST` 剥 CRC、`PS=0/FS=1/DM=1`（1000M 全双工） |
| 并发 | 全部回调落在同一条 `kIOServiceDefaultQueueName`，零锁 |

`TDTR/RDTR` 只有低 32 位寄存器（Linux 里也没有 `_HI` 版本），高位取自 `TDLR_HI`/`RDLR_HI`，所以环不跨 4 GB 边界就安全——4 KB 页对齐环天然满足。

**未实现（会明确返回"不支持"，不谎报）**

- 多段/TSO 帧：`desc_count > 1` 的路径没写，`getTSOOptions` 报不支持
- 多播哈希表（`MAC_HTR0..7`）
- 全部 offload（校验和 / TSO / VLAN 插入）—— `GetHardwareAssists` 返回 0
- 中断合并（`DMA_CH_RIWT` 没设，每帧一次中断，量大时中断率偏高）

## 验证边界（必须说清楚）

`./scripts/test.sh` 跑的两个东西都是**离线**的：

| 项 | 证明了什么 | 没证明什么 |
|---|---|---|
| `yt6801_host_verify` | 寄存器值与 MDIO 时序自洽，回环序列走通 | 真芯片认不认这些值 |
| `yt6801_ring_sim` | 环索引算术正确：不覆盖硬件持有的描述符、包不丢不重、TX 环能排空 | 硬件行为是否与模型一致 |

**真机能否过包，只有把 dext 装上去、`ifconfig enX up`、`ping` 一次才知道。** 在此之前不要声称"能联网"。
